# Dependencies are justified

## Metadata

| Field | Value |
|---|---|
| ID | coding.styles.generic.dependencies-justified |
| Description | Requires a concrete reason for introducing a dependency. |
| Scope | coding |
| Level | should |
| Tags | coding; style; dependencies; maintenance |

## Rule

A new dependency should be introduced only when its concrete value exceeds the complexity, compatibility, security, lifecycle, and maintenance costs it adds.

## Exceptions

None.

## Rationale

Dependencies transfer part of the system design and lifecycle to external code and therefore carry long-term cost.
